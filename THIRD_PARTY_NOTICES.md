# Third-party notices

This is a conservative inventory of all **650 registry packages in Cargo.lock**. It includes target-specific, build, development and optional resolution; it is **not a bill of materials proving what a release binary contains**. Each crate archive was verified against its Cargo.lock SHA-256 before extracting the original legal files. The CA project license does not replace these terms.

Regenerate offline with `python3 tools/generate_dependency_notices.py`; verify with `--check`. The generator runs Cargo metadata, never compilation or build scripts. Populate the cache first with `cargo fetch --locked` if needed. Upstream supplements are checked-in inputs with exact URLs and SHA-256 in [SOURCES.json](licenses/third-party/upstream/SOURCES.json).

Native system libraries and actual linkage must be checked per release target.

## Known limits

- This is a conservative Cargo.lock source inventory. It does not establish which code or notices are required for an individual executable, native system library, feature selection or target. Verify native linkage and packaged assets per release.
- Original legal files and leading comment/README attribution sections are retained. Embedded comment extraction is heuristic and is not a line-by-line ownership clearance of every source file. Upstream source ownership and the right to relicense third-party material are not inferred from Cargo metadata.
- Syntect supplemental licenses come from the submodule commits pinned by syntect v5.3.0. Its serialized assets do not carry a reproducible provenance manifest establishing the precise generation inputs. A bounded upstream syntax license scan identified C#, YAML and Rust exceptions; this is not exhaustive legal clearance of every compiled asset.
- Some archives omit standalone license files. Supplements retrieved at their recorded source commit preserve upstream notices where available; source comments and declared SPDX metadata remain distinct from the original full license text. Unresolved missing texts are listed explicitly.
- The original objc2/dispatch2 upstream LICENSE.md records uncertainty concerning Apple-SDK-derived bindings and Xcode SDK terms. Those upstream statements are preserved; a Rust SPDX identifier does not independently clear third-party SDK material.
- No original substantive primary license text was located by the conservative content check for: `adobe-cmap-parser@0.4.1`, `cesu8@1.1.0`, `dispatch2@0.3.1`, `mail-parser@0.11.5`, `objc2@0.6.4`, `objc2-app-kit@0.3.2`, `objc2-audio-toolbox@0.3.2`, `objc2-core-audio@0.3.2`, `objc2-core-audio-types@0.3.2`, `objc2-core-foundation@0.3.2`, `objc2-core-graphics@0.3.2`, `objc2-encode@4.1.0`, `objc2-foundation@0.3.2`, `objc2-io-surface@0.3.2`, `pdf-extract@0.12.0`, `rtorrent-xmlrpc-bindings@1.0.4`, `rustls-platform-verifier-android@0.1.1`, `simd_helpers@0.1.0`, `siphasher@1.0.3`, `stop-token@0.7.0`, `system-configuration-sys@0.5.0`, `type1-encoding-parser@0.1.1`, `winapi-i686-pc-windows-gnu@0.4.0`, `winapi-x86_64-pc-windows-gnu@0.4.0`, `zune-inflate@0.2.54`.
