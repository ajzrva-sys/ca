# Implementation Plan: `install_binary` Tool for ca

## Problem Statement

When ca's agent builds a binary via `cargo build`, the output lands in the
workspace. The agent needs to install it to `~/.local/bin/ca` (or another
destination) but cannot because:

1. The workspace boundary (`src/workspace.rs:201-234`) blocks writes outside
   workspace roots
2. The macOS sandbox (`src/sandbox.rs`) restricts file writes to workspace
   roots + tmpdir
3. `run_privileged` (`src/privilege.rs`) is only available in interactive TUI
   mode and requires sudo
4. `/usr/bin/install` is not in `CLOSED_PRIVILEGED_PROGRAMS`
5. In headless/service/subagent mode, `run_privileged` is stripped from the
   tool list

## Design Principles

- **Native Rust execution**: The tool runs as in-process Rust code, not a
  sandboxed subprocess. The macOS sandbox only applies to child processes;
  the ca process itself is unsandboxed.
- **No workspace resources declared**: By not declaring `ResourceFieldSpec`
  for the source/destination paths, `prepare_tool_invocation` skips workspace
  resolution entirely. The tool handler validates paths itself.
- **Available in all modes**: Registered with `Main + Subagent` profiles.
  No privilege escalation needed (writing to `~/.local/bin` doesn't need
  sudo for the owning user).
- **Reuse self_update.rs primitives**: `replace_executable`, `copy_exact`,
  `verify_file`, `sha256_file`, `create_private_file`, `check_private` are
  made `pub(crate)` and reused.

**Key decisions**:
- **No `ResourceFieldSpec`**: Neither `source` nor `destination` is declared
  as a resource. This means `prepare_tool_invocation` in `workspace.rs`
  will not attempt to resolve these paths against workspace roots. The
  tool handler does its own path validation.
- **`FilesystemWrite` capability**: Correct semantic classification.
- **`Main + Subagent` profiles**: Available everywhere the agent runs,
  including headless/service mode and subagent spawns.
- **`Mutating`**: Obviously modifies the filesystem.

#### 2.5.2 Implementation function

Add a new function in `tools.rs`:

```rust
async fn execute_install_binary(args: &Value) -> ToolExecutionResult {
    use std::path::PathBuf;

    let source = match args["source"].as_str() {
        Some(s) if !s.is_empty() => s,
        _ => return ToolExecutionResult::Failure(
            "install_binary requires a non-empty 'source' path".into()
        ),
    };

    let destination = match args["destination"].as_str() {
        Some(d) if !d.is_empty() => d.to_string(),
        _ => match std::env::current_exe() {
            Ok(path) => path.to_string_lossy().into_owned(),
            Err(error) => return ToolExecutionResult::Failure(format!(
                "Cannot determine current executable: {error}"
            )),
        },
    };

    let backup = args["backup"].as_bool().unwrap_or(true);
    let verify = args["verify"].as_bool().unwrap_or(true);

    // --- Validation ---
    let source_path = PathBuf::from(source);
    if !source_path.is_file() {
        return ToolExecutionResult::Failure(format!(
            "Source is not a regular file: {source}"
        ));
    }

    let dest_path = PathBuf::from(&destination);
    let dest_parent = match dest_path.parent() {
        Some(parent) => parent,
        None => return ToolExecutionResult::Failure(
            "Destination has no parent directory".into()
        ),
    };

    // Ensure destination parent directory exists
    if !dest_parent.is_dir() {
        return ToolExecutionResult::Failure(format!(
            "Destination directory does not exist: {}",
            dest_parent.display()
        ));
    }

    // Reject symlinks in source
    if std::fs::symlink_metadata(&source_path)
        .is_ok_and(|m| m.file_type().is_symlink())
    {
        return ToolExecutionResult::Failure(
            "Source must not be a symlink".into()
        );
    }

    // Reject symlinks in destination (if it exists)
    if dest_path.exists() {
        if std::fs::symlink_metadata(&dest_path)
            .is_ok_and(|m| m.file_type().is_symlink())
        {
            return ToolExecutionResult::Failure(
                "Destination must not be a symlink".into()
            );
        }
    }

    // Compute source SHA-256 and size
    let source_metadata = match std::fs::metadata(&source_path) {
        Ok(m) => m,
        Err(error) => return ToolExecutionResult::Failure(format!(
            "Cannot read source metadata: {error}"
        )),
    };
    let source_size = source_metadata.len();
    let source_sha256 = match crate::self_update::sha256_file(
        &source_path, source_size
    ) {
        Ok(hash) => hash,
        Err(error) => return ToolExecutionResult::Failure(format!(
            "Cannot compute source SHA-256: {error:?}"
        )),
    };

    // --- Backup existing destination ---
    if backup && dest_path.exists() {
        let timestamp = chrono::Utc::now().format("%Y%m%dT%H%M%SZ");
        let backup_path = dest_path.with_extension(format!(
            "bak.{timestamp}.{}",
            &source_sha256[..8]
        ));
        if let Err(error) = std::fs::copy(&dest_path, &backup_path) {
            return ToolExecutionResult::Failure(format!(
                "Cannot create backup at {}: {error}",
                backup_path.display()
            ));
        }
    }

    // --- Atomic replace ---
    // Uses the same pattern as self_update::replace_executable:
    // 1. Copy source to a temporary file in the destination directory
    // 2. Rename temporary over destination (atomic on same filesystem)
    // 3. Sync the parent directory
    // 4. Verify the installed file
    if let Err(error) = crate::self_update::replace_executable(
        &source_path,
        &dest_path,
        source_size,
        &source_sha256,
    ) {
        return ToolExecutionResult::Failure(format!(
            "Install failed: {error:?}"
        ));
    }

    // --- Post-install verification ---
    if verify {
        let installed_metadata = match std::fs::metadata(&dest_path) {
            Ok(m) => m,
            Err(error) => return ToolExecutionResult::Failure(format!(
                "Post-install verification failed: cannot read installed \
                 metadata: {error}"
            )),
        };
        let installed_sha256 = match crate::self_update::sha256_file(
            &dest_path, installed_metadata.len()
        ) {
            Ok(hash) => hash,
            Err(error) => return ToolExecutionResult::Failure(format!(
                "Post-install verification failed: {error:?}"
            )),
        };
        if installed_sha256 != source_sha256 {
            return ToolExecutionResult::Failure(format!(
                "Post-install verification failed: SHA-256 mismatch. \
                 Expected {source_sha256}, got {installed_sha256}"
            ));
        }
    }

    // --- Check executable permission ---
    #[cfg(unix)]
    {
        use std::os::unix::fs::PermissionsExt;
        let mode = std::fs::metadata(&dest_path)
            .map(|m| m.permissions().mode())
            .unwrap_or(0);
        if mode & 0o111 == 0 {
            return ToolExecutionResult::Failure(format!(
                "Installed file is not executable (mode {:o})", mode
            ));
        }
    }

    ToolExecutionResult::Success(format!(
        "Installed {} -> {} (SHA-256: {}, {} bytes){}",
        source_path.display(),
        dest_path.display(),
        &source_sha256[..16],
        source_size,
        if backup { " [backup created]" } else { "" }
    ))
}
```

**Important**: This function uses synchronous std::fs operations, but
the actual file operations from `self_update.rs` are synchronous (blocking).
Since these are fast local-disk operations (copy + rename + sync), blocking
the async runtime briefly is acceptable. If this becomes a concern, wrap
the call in `tokio::task::spawn_blocking`.

### 2.6 TUI Dispatch (main.rs)

**File**: `src/main.rs`

through `execute_prepared_tool_in_workspace_policy_owned_with_skills` which
eventually calls `execute_tool_with_context` where the intercept lives.

**No special TUI handling needed.** Unlike `run_privileged`, `install_binary`
doesn't need:
- Administrator approval (writes to user-owned directory)
- Credential handoff (no sudo)
- Special preparation flow

The tool flows through the normal approval pipeline. The `Mutating` mutation
classification means it will be subject to whatever approval mode is active
(Yolo, AutoReview, or explicit prompt).

**However**, there's a subtlety: `prepare_tool_invocation` in `workspace.rs`
(line 261-377) iterates over `spec.resources` to resolve paths. Since we
declared no resources for `install_binary`, the paths pass through unchanged.
This is the correct behavior.

## Test Plan

### Unit Tests

1. **Args validation**: Verify `InstallBinaryArgs` deserializes correctly
   with all fields, with only required fields, and rejects unknown fields.

2. **Registry test updates**: Update the existing `builtins_are_unique_and_schema_validation_agrees`
   test with the new count (93) and a valid args fixture.

3. **Profile test updates**: Update `profiles_mutations_capabilities_and_resources_are_centralized`
   with the new Main count (88) and assertions.

4. **Self-update function visibility**: Verify the made-pub functions compile
   from `tools.rs`.

### Integration Tests

5. **Happy path**: Build a test binary, call `install_binary` with source
   pointing to it and a temp directory destination, verify:
   - Binary is copied and executable
   - SHA-256 matches
   - Backup is created
   - Success message is correct

6. **Missing source**: Call with non-existent source, expect failure.

7. **Symlink rejection**: Call with symlink source, expect failure.

8. **Destination parent missing**: Call with destination in non-existent
   directory, expect failure.

9. **No-backup mode**: Call with `backup: false`, verify no backup file
   created.

10. **No-verify mode**: Call with `verify: false`, verify install succeeds
    without post-install hash check.

11. **Default destination**: Call without `destination`, verify it uses
    `std::env::current_exe()`.

12. **Workspace bypass**: Call with source inside workspace and destination
    outside workspace (e.g., `/tmp/test-install-dir/`), verify it succeeds
    without workspace boundary errors.

### Headless Mode Test

13. **Headless execution**: Verify `install_binary` is available in headless
    mode tool set (not stripped by tool selection constraints).

### Sandbox Test

14. **macOS sandbox bypass**: On macOS with sandbox-required mode, verify
    `install_binary` can write to `~/.local/bin/` while `run_command` with
    `cp` cannot.
