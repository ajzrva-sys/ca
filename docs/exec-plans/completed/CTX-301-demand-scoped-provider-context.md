# CTX-301 — Relevant context through demand retrieval

Status: completed and installed as signed ca 0.1.47; final source/install/real-provider acceptance passed (2026-10-24).

## Normal entry point and problem

Normal TUI/headless/service requests automatically include a full available skill catalog (up to 8,000 tokens), broad native memories without query relevance and foreign historical notes. Skill bodies are already activated lazily, but catalog metadata and recalled memories consume tokens before the task needs them. User requests current session/project context, pertinent memory/skill retrieval as needed, permanent storage and clear background-learner linkage.

## Small complete change

- Keep authored project/global instructions, current canonical conversation/checkpoint, explicit attachments and explicitly loaded skills. Replace automatic available catalogs and memory/foreign-note bodies with compact authored discovery guidance.
- Add read-only bounded skill_search and memory_search to existing tool execution/permissions/filtering. Skill search returns matching metadata only; exact/hash activation and file view retain validation. Memory search requires a query, defaults to current canonical project's store plus query-matched global lessons, and permits explicit global-only search. No other project's store is loaded by default; no match/empty query cannot dump a corpus.
- Read memory stores freshly in a blocking worker on each explicit search, so a background Dream publication is visible without preloading it or restarting. Existing storage paths/provenance remain; no production-state rewriting.
- Stop recognizing generic 'I prefer/I always' as explicit global authority when learning. Existing cross-workspace corroboration remains; exact explicit cross-project words can authorize global use. Report residual historical misclassification as a compatibility bound rather than rewriting memories.
- Keep schemas compact: when skill discovery is available, backend validation rather than exhaustive unrelated skill-ID enums binds activation/view. Default session search stays current project; explicit global history search remains possible.

## Background learning link

Dream persists approved/validated records in profile user or canonical-workspace memory stores. Demand memory search routes to the current project's hash and matches reusable user lessons by concrete task terms; returned entries retain scope/provenance. Distill publishes enabled hash-bound skill generations. Demand skill search finds matching metadata, then activation/view pulls instructions when needed. Existing generation/publication formats remain unchanged in this scope. This is retrieval admission repair, not a replacement learning framework or bulk migration.
