# Configuration

## Storage and credentials

Default runtime settings live in `~/.config/ca/config.toml`. Named profiles isolate
configuration and storage; `ca --profile NAME` selects one. Names start with a
lowercase letter and contain lowercase letters, digits, `-`, or `_` (at most 64
characters). Runtime files and credentials belong outside the source repository.

Provider `api_key` fields can reference an environment variable, such as
`${CA_PROVIDER_API_KEY}`. Populate that variable through your shell or secret
manager. Do not paste its value into documentation, issue reports, or source.
The application also has provider secret-store integration; use its provider
management flow when that is appropriate for your installation.

## Minimal provider example

This is a template for a new configuration. Replace the endpoint and model ID
with values supplied by your provider; they are deliberate placeholders:

```toml
[providers.example]
base_url = "https://provider.example/v1"
api_key = "${CA_PROVIDER_API_KEY}"
protocol = "chat_completions"
models = ["your-model-id"]

[defaults]
provider = "example"
model = "your-model-id"
```

The configured default provider must name a provider table. The default model
must be supported by that route. `models` supplies explicit model identifiers;
live discovery and cached/configured metadata have separate freshness states.
Use `ca --list-models` to inspect configured models.

The default configuration generated by the application contains several starter
routes. Those entries still need valid credentials or a locally running endpoint.
Their existence does not verify current provider availability.

## Subagents across providers

The parent and its helpers may use different configured providers. Connect each
provider and configure its exact model IDs first. A DeepSeek parent can then
select a configured OpenAI or native Codex helper without changing the parent
route. The model-visible `list_agent_routes` tool lists configured identities
without reading credentials or contacting the providers; its result is not an
authentication check.

For a task-specific choice, `task`, `spawn_agent`, and each `spawn_agent_batch`
item accept an exact child route:

```json
{
  "task": "Inspect the parsing boundary",
  "tools": ["read_file", "search_files", "glob", "list_dir"],
  "route": {"provider": "openai-codex", "model": "your-configured-model-id"}
}
```

Use the identities returned by `list_agent_routes`; unknown pairs fail before
child admission. An exact `route` bypasses automatic cost routing and cannot be
combined with `complexity`. Each child retains its normal tool grants and
lifecycle controls regardless of its provider.

Without a task-specific route, delegation defaults to the parent's current
provider/model. To set a different default for helpers, configure:

```toml
[delegation]
mode = "fixed"

[delegation.route]
provider = "openai-codex"
model = "your-configured-model-id"
```

Both identities must already exist in the provider configuration. An exact
task-specific route overrides this default. Learned or explicitly requested
complexity routing remains a separate option and requires its configured route
and pricing information.

In `mode = "learned"`, `allowed_routes` limits the candidates before automatic
cost ranking. A cheaper route outside that set cannot exclude a qualifying
permitted route; the requested capability floor and pricing freshness still
apply. The current mode selects from pricing/capability metadata and does not
learn task suitability or health from completed-task outcomes.

## Protocol and model capability

Supported `protocol` values are `chat_completions`, `openai_responses`,
`anthropic_messages`, and `google_generate_content`. Omission retains Chat Completions behavior. Select the
protocol supported by the exact endpoint; do not infer it from the provider name.
Reasoning, tool use, context limits, prompt caching, and continuation behavior
also depend on model metadata. The source schema in `src/config.rs` and provider
adapters in `src/agent/provider.rs` define accepted settings.

Local OpenAI-compatible endpoints can be configured as routes. Managed GGUF
execution is separately available through `ca runtime` and `ca local`; it
requires an explicitly registered runtime and model. A provider entry does not
install or start an external server.

## Provider filter

`[provider_filter]` sits on the bytes between ca and every provider. You write
the lists. The filter does not ask a model to choose words.

A config file has three jobs. **Stop** ends the session when that text
appears. **Hide** rewrites outbound text and leaves the session running.
**Pages** rewrites the words of a fetched page.

The first enabled snapshot stays for that process. A later reload cannot turn
it off or replace its rules. Restart ca to change it. A trip stays stuck for
the process. Exit and start a new process to continue. Tools still open the
real file and fetch the real URL.

`enabled = true` with nothing in the lists prints `filter on, nothing armed`.
The `FILTER ON` banner stays up. The row under it says `nothing armed`.

### Stop

```toml
[provider_filter]
enabled = true
trip_file = "/absolute/path"

[provider_filter.stop]
phrases = ["secret"]
urls = ["http://stop.com/stop"]

[[provider_filter.stop.rules]]
id = "kill-switch"
pattern = "A-123"
```

A phrase matches in any case, in a request and in a reply. `secret` matches
`Secret` and `"secret"`. A URL matches that URL: scheme, host, port, and
path. `http://stop.com/stop` matches that path. A different path stays.
`http://anything.else` stays. The provider error names `phrase-1`, `url-1`,
or the rule id. The status line on this machine shows the matched text, for
example `stopped on "secret", in the reply`.

`trip_file` is a regular file. Trimmed contents `stop` trip the session. The
status line says `stopped on "trip file"`. A symlink or an unreadable file
fails closed.

Request scans include the request body, file reads, tool and command output,
and attachments, including bytes a tool would have omitted. Phrases, URLs,
and rules together accept at most 32 entries.

### Hide

```toml
[provider_filter]
enabled = true

[provider_filter.hide]
words = ["patient-name"]
all_urls = true

[[provider_filter.hide.pairs]]
from = "stop.txt"
to = "go.txt"

[[provider_filter.hide.urls]]
from = "http://stop.com"
to = "http://go.com"
prefix = false
```

A hide word, pair, or URL never stops the session. `patient-name` becomes
`ca-kw-01` on the way out. `stop.txt`, `Stop.txt`, and `STOP.TXT` become
`go.txt`. The file on disk keeps its name. A hide URL rewrites that URL.
`prefix = true` also rewrites child paths. `prefix = false` leaves
`http://stop.com/child` as written. `all_urls = true` rewrites the authority
of every absolute `http` or `https` URL to an opaque `ca-rNN` stand-in
(`http://ca-r01.invalid`), keeping the path, query, and fragment, so the
provider does not see destinations but the URL's shape stays visible. Tool and
output schema identifiers, references, and validation values keep their exact
values; URLs in schema titles and descriptions are still hidden. When a
page stand-in is enabled, the path words are tokenized too, so slugs stay
hidden. The local view puts each authority back. Tools still fetch the real
URL. The reply view puts the original spelling back.

The same text in stop and hide fails config load. The error names both sides
and quotes the text. An explicit pair still wins over an automatic `ca-kw-NN`.
Hide pairs and hide URLs together accept at most 32 entries. Hide words accept
32 of their own.

### Pages

```toml
[provider_filter]
enabled = true

[provider_filter.pages]
stand_in = "latin"
images = true
```

`pages = "latin"` rewrites words in a `web_fetch` page into a built-in Latin
list. `pages = ["alpha", "beta"]` uses those words. `off` is the default.
`images = true` replaces pictures in the outbound copy with `[image]`. The
picture on screen, the file on disk, and the fetch stay real. A normal
`https` URL stays.

The user's own message stays. Tag names stay. A URL inside the page stays.
The same spelling always becomes the same `«…»` token, and the view puts the
original word back. A stop phrase in a fetched page is judged on the page
itself. The request is judged again after the rewrite.

### What you see

The top row is one centered `FILTER ON` on a cyan bar, and nothing else. It is up whenever the filter is on, including when the lists are empty. The row under it is one line,
for example `stop 3 words, 1 url · hide 2 · pages latin · images on`, or `nothing armed`. After a
trip that row becomes `stopped on "secret", in the reply`. The origin is
`request`, `reply`, or `fetched page`.

`/filter` opens that list. It works during a turn. While the filter is off,
the list ends with `/filter on turns it on for this process.` `/filter on`
arms the filter loaded at startup for this process and does not write the
config file. There is no off switch. A trip stays stuck.

On a wide terminal the side pane shows the same summary, then the provider
body. Below 80 columns the pane stays hidden and the second row carries the
summary. Below 3 rows only `FILTER ON` is painted and the summary goes to the
status line.

Startup says `filter loaded: stop 2, hide 1. Restart ca to change it.` A
later edit that would change the armed filter leaves this process on the copy
from startup and says `filter file changed; this process is still on the copy
from startup.`

### Check and one process

`ca filter check` prints the armed summary, how an older file was read, and
each entry. It does not contact a provider and it does not install the
filter. `--text` runs one sample through the request path:

```
would stop on "secret", in the request
would send: hello
```

`--file PATH` reads a saved HTML or text page and prints the same `would
send:` / `would stop` lines after hide words and page stand-in rewrite the
raw body. Use it to preview what a provider would see for a local page
without contacting a provider. `--file` and `--text` cannot be combined.
Files above 8 MiB are rejected; the printed body is truncated at 256 KiB.

`--hide WORD` (repeatable), `--hide-urls`, and `--pages SPEC` (`off`, `latin`,
or a comma-separated word list) add or replace those lists for this run only
and do not write the config file. `--hide-urls` is the one-run form of
`[provider_filter.hide] all_urls = true`. With any of these flags the preview
arms even when the loaded file is empty or absent.

Exit 0 when the file is valid, including when the sample would stop. Exit 1
when the file is invalid. A validation error quotes the bad value. The
provider error and the withheld tool string keep the rule id.

`ca --filter` sets `enabled = true` for this process and does not write the
config file. It works in the TUI and in headless mode, including
`--profile bare`. `/filter on` does the same thing after the TUI is already
open. There is no mid-session off switch.

### URLs, masks, and older files

A stop URL is exact. A hide URL is exact unless `prefix = true`. An older
`[[adjustments]]` entry whose `from` is an `http` or `https` URL still
rewrites child paths. `ca filter check` prints `prefix on (from adjustments)`
for those.

A URL left in `phrases` stays a case-insensitive substring. Check names that
matcher.

`mask = true` on a stop phrase or URL rewrites it on the way out (`ca-kw-NN`
or `http://ca-rNN.invalid`) and still stops if the original text comes back.
The default leaves the text as written and stops on a match.

```toml
[[provider_filter.stop.phrases]]
text = "secret"
mask = true
```

Older keys still load. `phrases`, `urls`, and `rules` become stop entries.
`obfuscate = true` sets `mask = true` on those phrases and URLs.
`obfuscation_patterns` become hide words. `adjustments` become hide pairs.
A word listed in both `phrases` and `obfuscation_patterns` becomes one masked
stop. Check prints `secret: masked stop (listed in phrases and obfuscation_patterns)`.
The same word in a new stop table and a new hide table fails load. Setting
both a new table and the old key for the same list fails load and names both
keys.

`page_stand_in` and `page_stand_ins` still load, including `characters` and
`phrases`. Setting both `pages` and `page_stand_in` fails and names both keys.
`placeholder_images = true` is the same switch as `pages.images`. Setting both
fails and names both keys.

Headless exit is 11 when the filter stops the run. A match may span two reads
inside an 8 KiB window.

## Profiles and process overrides

`default` selects ordinary storage. Named profiles select isolated whole-file
configurations. `bare` reads the default configuration while disabling persistent
writes and optional run capabilities. Bare mode is a reduced execution profile;
it is distinct from `--no-session`, which only keeps the run and its branches
out of saved-session storage.

Useful process overrides include:

```sh
ca --profile work --workspace /path/to/project
ca --mode ask
ca --plan
ca --no-session --prompt "Explain this file"
ca --add-dir /path/to/another/root
```

`--sandbox required|policy-only|off` selects the configured execution boundary
for this process. Workspace trust, tool authorization, network grants, and the
sandbox remain distinct decisions. `--trust` is an explicit headless launch
choice; it does not configure a permanent universal grant.

## Extensions and setting provenance

The config also supports MCP, LSP, skills, plugins, hooks, permission rules,
model profiles, route presets, sessions, memory, learning, review, and automation.
Configure only the integrations you intend to run. Use their dedicated guides
and source definitions instead of adding guessed keys.

`ca config explain` reports setting origins without displaying values. Use
`ca --doctor` for local readiness; add `--connect` only when you intend to send
provider probes. See [Troubleshooting](TROUBLESHOOTING.md) for missing environment
references and protocol mismatches.

## Selective context pruning

Pruning is automatic for ordinary coding conversations. It reduces only old, successful text tool results in outbound requests; saved history, exports and session recall retain the original results. The newest two human turns, skill content, errors, private results and media remain protected. Context inspection reports estimated savings. Checkpoint generation and independent evaluation receive complete evidence.

The usable input capacity is the configured compaction threshold, or 80% of a known context window. Pruning protects a recent tool-output budget of 25% of that capacity (up to 40,000 estimated tokens) and requires savings of 10% (up to 20,000). Without a known capacity, those fixed 40,000/20,000 limits apply.

To disable it:

```toml
[context_pruning]
enabled = false
```

## Formatting native file edits

Formatting is opt-in. Presets use already installed `rustfmt`, `prettier`, and `ruff`; CA does not install them. Custom rules precede presets and the first matching rule wins. Commands receive proposed contents on stdin and return the complete replacement on stdout. `$FILE` supplies the original absolute file path. Each invocation has a 10-second deadline and the existing reversible-file size limit.

```toml
[formatting]
enabled = true
presets = ["rustfmt", "prettier", "ruff"]

[[formatting.custom]]
extensions = ["txt"]
command = ["/usr/bin/tr", "a-z", "A-Z"]
```

Formatter execution also requires an allowed `run_command` policy; saved Ask or Deny rules are respected, and child agents retain their own command limits. An unavailable or unapproved formatter keeps the requested unformatted edit and shows a warning. Formatting uses candidate bytes before final edit approval and publication, so recovery and undo retain one original-to-final receipt. Undo and redo restore bytes without rerunning formatting. Shell and external-tool edits are unaffected.
